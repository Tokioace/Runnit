# Finish recovery

The prior finish payload only lived in a React ref. Persist one account-scoped, allowlisted aggregate finish for up to four hours of eligibility; no raw location, motion samples, or auth token. Restoration requires a matching server-confirmed participant, duel, start timestamp and distance; do not start the GPS race again. Retry is manual and serialized in this tab, checks the current session, and submits the original rounded time. The server RPC remains idempotent. Local state is discarded on confirmed completion/abandonment, and old records cannot delete newer ones. The expiry is checked when the matching record is read; browser storage may otherwise retain an inaccessible stale record. Storage denial falls back to memory. Cross-tab requests can still overlap; server idempotency is required. Browser data is not trusted evidence. Test real Safari/PWA reload, offline finish and reconnect, logout/account switch, opponent completion and abandonment on two phones. No visual layout or live database change.
