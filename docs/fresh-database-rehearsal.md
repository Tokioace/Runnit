# Fresh database rehearsal
CI now replays the checked-in baseline schema, duel RPCs, lifecycle SQL, historical migrations and six staged candidates together in a fresh PostgreSQL 17/PostGIS 3.5 service. The test-only erasure gate follows. This is a deliberately explicit installation order for the disposable test, not a generated production migration or a claim that the historical files alone can bootstrap Supabase. The cron script is excluded (no scheduler in this fixture). A hard database-name/empty-schema guard and one transaction keep execution isolated; no hosted database credentials or data are used. Tests exercise actual geographic column types and nearby RPC, profile trigger and default ranking opt-in, RLS and catalog privileges, realtime publication membership, a real join/ready/abort sequence, early finish rejection, owner-only preferences/deletion requests, stale session read denial, and public empty leaderboard. Existing isolated fixture still tests concurrent finishes and erasure. Auth schemas/roles/functions here are mocks, not real GoTrue, PostgREST, Realtime transport, or cloud ACL defaults. Hosted test project and API verification remain required; candidates stay outside active migrations. See Supabase local development workflow documentation (https://supabase.com/docs/guides/local-development/cli-workflows) for a real local stack. No production changes or paid hosted database provisioning.
