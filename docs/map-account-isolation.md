# Map account isolation
The map previously used an independent useSupabaseUser hook in addition to App's auth hook. A direct authenticated A-to-B transition could retain the old map component's state and refs. App now passes its auth object to MapScreen and keys the route element by user ID (or guest). React remounts the map only when the account identity changes, not for ordinary token refresh or profile metadata updates. Existing map UI, layout, route and guest gating stay the same. On unmount the layout effect retires the old account ref synchronously, before passive channel cleanup. Recovery callbacks, delayed join/ready/abort/cancel/host confirmations, host preflight continuation, and late finish callback are checked against the retired account ref. Pending finishes and active race IDs remain in their existing account-scoped local storage; a remount doesn't delete them. Already dispatched server mutations cannot be canceled by this change; database authorization remains authoritative, and this is not a general cross-account transport isolation guarantee. Four source-contract regression tests; actual React/device account-switch behavior requires practical validation. No SQL, production or style changes.
