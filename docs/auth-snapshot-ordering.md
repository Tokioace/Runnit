# Auth snapshot ordering
A pending initial getSession() can complete after the SDK has already notified a subscriber about a login, logout or user change. The hook now captures a per-subscription revision and rejects an initial success, error or loading update once an auth event has superseded it. Cleanup closes the guard before unsubscribing, including React StrictMode effect replacement. Display-name sync and signOut no longer overwrite local identity after their asynchronous completion; the SDK USER_UPDATED / SIGNED_OUT events remain authoritative. No changes to authentication methods, token persistence, Supabase policies, UI or existing signOut scope. Five regression tests exercise delayed success/error, logout, account switch, closure and hook wiring. These tests model event ordering, not real Supabase network or cross-tab event delivery. Physical-device and hosted tests remain open.
