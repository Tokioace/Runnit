# Beta ranking plausibility candidate

Not deployed. Existing two public opt-in leaderboard RPCs retain their signatures, explicit opt-in rules and guest visibility. Both runners must satisfy the same 50/75/100 m, 15 m/s average-speed ceiling and 2 s clock-tolerance bounds as the staged submission guard, including a recorded start and submission timestamp. A pair with an invalid or missing time is excluded from all six public Beta categories, not deleted. Invalid optional speed/acceleration values cannot set records; valid time results remain eligible. Historical, private, incomplete and unsupported races are not certified. A client cannot earn verified status through a JSON flag, motion evidence or plausible times.

These filters reject some impossible claims but cannot detect plausible fabrications. Thresholds are provisional until real device validation. Wins/streaks remain Beta statistics, not official rankings. Private history is unchanged. No UI changes, database changes, or main changes. The isolated PostgreSQL fixture checks valid pairs, implausible legacy times, missing start, unsupported distance, insufficient server elapsed time, non-finite metrics, opt-in privacy and data preservation under anon privileges. The full production schema, real Supabase API grants, test project, and field validation remain necessary before a generated migration is activated.
