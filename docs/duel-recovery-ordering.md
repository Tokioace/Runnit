# Duel recovery request ordering
The existing 4-second match recovery poll, focus and visibility callbacks previously allowed concurrent REST requests. Their completion order could differ from request order, including after a new Realtime-confirmed transition. Recovery is now single-flight with one coalesced pending request. A revision captured before the initial read becomes stale after a confirmed match, abort, completion or local dismissal; both reads check that revision, current account and effect lifetime before updating. The follow-up active-ID read also checks the same ID remains active and validates participant identity. Missing rows and network failures do not imply a race ended; pending finish data are not discarded. Queue closure prevents follow-up requests after unmount; in-flight reads are ignored, not forcibly canceled. The existing interval, countdown, UI and SQL remain unchanged. Four regression tests cover overlap, failures, closure and stale-account/revision handling. Actual mobile suspension and two-device tests remain necessary. This is not a full ordering protocol for every realtime/REST action.
