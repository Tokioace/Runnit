# Duel realtime event lifecycle
Fixes the browser map's handling of Supabase Postgres Changes. A DELETE normally has an empty new record and may contain only the old primary key; old is explicitly selected and only matching local markers are removed. No outcome or participant status is inferred from deletion. Validate event schema, table, type, UUIDs and allowed status before processing inserts/updates. Close subscription lifetime synchronously before removing the channel; late payload/status callbacks cannot act after cleanup. Reconcile discovery after subscription/reconnection. Existing match polling and server authority remain unchanged. No UI layout or database changes. Five automated tests cover payload normalization, malformed records, callback lifetime and integration contract. These tests do not prove hosted Realtime transport security; in particular DELETE notifications cannot be filtered by RLS in the same manner as inserts/updates, and must not be treated as an authorization signal. Real two-device, reconnect and revoked session tests on an isolated Supabase project remain required.
