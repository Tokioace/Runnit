# Profile account isolation and mutation preflight
ProfileScreen now shares the App authentication source and remounts on a different user ID or guest, keeping ordinary token refreshes stable. Drafts, open dialogs, password inputs, consent state and private history are not reused by the next account. The per-hook identity generation is updated from accepted session snapshots and auth events, and retired on cleanup. Password and display-name changes require a current account generation and a server getUser identity matching the intended user before the SDK updateUser call; returned identity and generation are checked afterward. Profile metadata and consent writes also check the generation. A logout or A-to-B-to-A change invalidates pending checks. No raw password storage, layout changes, SQL or production mutations. This is a UI-side preflight, not atomic binding of SDK requests to a specific token: an account change after the final check but during SDK lock acquisition/transport is still possible, and already dispatched writes are not reversible. Real multi-tab and device testing is required. Supabase Auth and RLS remain authoritative. Existing logout scope is unchanged. Five tests cover guard behavior and integration contracts.
